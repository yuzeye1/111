# 帧集 FrameLab · 项目结构与本地运行说明

> 架构对齐 flaskproject：**根目录扁平结构**，`app.py` 唯一入口。
> 三个平台 = 三套独立路径，共享同一个应用、账号与数据库。
> 所有配置均为项目相对路径（`BASE_DIR` 计算），云端部署无需改动。

---

## 一、三个平台怎么分（核心架构）

三端不是三个页面，是**三个平台**，路径各自独立：

| 平台 | 页面路径 | API 命名空间 | 内容 |
|---|---|---|---|
| **主站（客户端）** | `/`、`/index`、`/login`、`/register`、`/profile/<id>` | `/api/market/*` | 作品广场、派单大厅、我的接单、甲方中心（认证/发布/验收/结算）、实习通道、兴趣社区推送 |
| **教育端** | `/edu/`、`/edu/index` | `/edu/api/*` | 美学赏析库、收藏对标、每日推送、L1-L4 闯关实训、六维评分、成长雷达 |
| **创作端** | `/create/`、`/create/index` | `/create/api/*` | 灵感 AI 六维方案、专业工具跳转、作品上传、云端作品集、工作流沉淀 |
| 账号系统（三平台共用） | — | `/api/auth/*` | 邮箱验证码注册（30积分+1GB）、登录（JWT）、发验证码、找回密码、/me |

部署后即：`域名/index`（主站）、`域名/edu/index`（教育端）、`域名/create/index`（创作端）。
各平台页面独立（`templates/edu/`、`templates/create/`），仅通过少量入口互跳，
后台数据互通：教育端通关等级决定主站接单门槛，创作端作品出现在主站广场。

## 二、本地运行

### cmd（Windows）——一键脚本

项目根目录执行（或双击 `run.cmd`）：

```cmd
run.cmd
```

> 说明：`.venv` 由 Anaconda Python 3.8 创建，cmd 默认 PATH 缺少其 OpenSSL DLL
> 目录（`Anaconda3\Library\bin`），run.cmd 启动前自动补上。
> **此脚本只影响本机开发启动，不改项目任何配置，不影响云端部署。**

### Git Bash / Qoder 终端

```bash
.venv/Scripts/python.exe app.py      # 或 flask run（.flaskenv 已配置）
```

### 云端（生产，gunicorn）

```bash
gunicorn -c gunicorn.conf.py app:app   # 127.0.0.1:8010，nginx 反代域名
```

## 四、数据存在哪里（三处）

| 数据 | 位置 | 说明 |
|---|---|---|
| 所有业务数据 | `instance/framelab.db` | 单文件 SQLite；删掉=清空，可用 seed.py 重灌 |
| 上传的作品文件 | `static/uploads/` | uuid 重命名；数据库只存 URL 和字节数 |
| 密钥配置 | `.env`（从 `.env.example` 复制） | SECRET_KEY / JWT 密钥 / DATABASE_URL / 后续模型 Key |

作品封面 `cover` 两种取值：`grad:linear-gradient(...)` 渐变占位；`/static/uploads/xxx.png` 真图。

## 五、一次请求的链路（以「提交闯关作业」为例）

```
浏览器 edu/index.html
  └─ API.post('/edu/api/courses/5/submit', {title})   ← api.js 自动带 JWT
       ▼
app.py（唯一入口，装配好的 app + JWT 解析）
       ▼
education.py  submit_course()      ← 蓝图层：校验、编排
       ▼
aesthetics.py  score_artwork()      ← 算法层：六维评分
       ▼
databaseinit.py  CourseProgress     ← 数据层：写库
       ▼
utils.ok() → JSON {code:0, msg:'通关成功', data}
       ▼
浏览器渲染六维得分卡
```

分层规则：蓝图只做校验编排（薄）；算法文件是纯函数；模型只管表和 to_dict()。

## 七、管理后台 / 消息 / 互动 / 派单报名制（二期新增）

### 管理后台（`admin.py` + `/admin/`）

- 登录：`/admin/login`，管理员邮箱+密码（`POST /api/admin/login` 校验 `is_admin`）。
- 鉴权：`admin_required` 装饰器解码 JWT 并校验 `User.is_admin`；页面请求重定向登录页，接口请求返回 401/403 JSON。
- 仪表盘（单页侧栏 tab）：概览计数 / 用户管理（封禁·解封·设管·撤管·重置密码）/ 作品下架 / 素材下架 / 订单仲裁 / 反馈回复送 Token / 公告下发 / 邮件通知。
- 入口：导航栏对 `is_admin` 用户显示“管理后台”。
- 生产引导：`FLASK_CONFIG=production` 且用户表为空时，按 `ADMIN_EMAIL/ADMIN_PASSWORD` 自动建管理员（`is_admin=True`）。

### 消息系统（`Message`）

- `kind`：invite 邀约 / review 评审 / order 需求 / coop 合作 / system 系统（公告）。
- 触发：闯关提交→review；订单报名/选定/交付/验收/仲裁→order；公告/封禁/重置密码→system。
- 导航红点：`base.html` 每 30s 轮询 `/api/market/messages` 未读数；个人中心支持“全部已读”（`POST /api/market/messages/read-all`）。

### 互动系统（`/api/social/*`）

- 点赞：`POST /api/market/artworks/<id>/like`（切换），`GET` 返回点赞态。
- 评论：`GET/POST /api/social/artworks/<id>/comments`、`DELETE .../comments/<cid>`（本人或管理员）。
- 关注：`POST /api/social/users/<id>/follow`（切换），`GET /api/social/users/<id>/stats`（粉丝/关注/获赞）。

### 派单报名制（`OrderApplication`）

- 设计师“报名接单”（`POST /api/market/orders/<oid>/apply`）提交方案；
- 甲方“管理报名”（`GET .../applications`）并“选定创作者”（`POST .../select/<app_id>`）→ 设 taker + 冻结保证金 + 双方消息，其余报名置 rejected。

## 八、常见问题

- **改代码不生效？** 开发模式 `debug=True` 自动重启；gunicorn 需手动重启进程。
- **端口被占用？** 开发固定 5001（避开同机 flaskproject 的 5000）。
- **`__pycache__/`？** 字节码缓存，可随时删，.gitignore 已忽略。
- **乱码？** 运行脚本统一加 `-X utf8`。
- **Windows cmd 下 _ssl 报错？** 用 `run.cmd` 启动（自动补 Anaconda DLL 路径）。
- **为什么模板/静态文件在根目录？** `Flask(__name__)` 以 app.py 所在目录为根，自动找根目录的 `templates/` 和 `static/`——与 flaskproject 完全一致。
